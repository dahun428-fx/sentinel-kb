# 테스트 계획서 (STP)

## 1. 목적과 범위
sentinel-kb의 기능·품질 요구사항이 충족됨을 검증한다. 일반 소프트웨어 테스트에 더해 **검색·생성 품질 평가(eval)** 를 정식 게이트로 포함하는 것이 본 계획의 특징이다. RAG 시스템은 예외 없이 동작하면서도 품질이 낮을 수 있어, 통과/실패만으로는 품질을 보증할 수 없다.

## 2. 테스트 레벨
| 레벨 | 대상 | 기법 | 환경 |
|---|---|---|---|
| 단위 | chunker, RRF, 인용 파서, sanitizer, 스키마 | 동등분할·경계값 | 인메모리, 목 |
| 통합 | 라우트↔DB, MCP 계약 | 인터페이스 기반 | 테스트 클러스터 |
| 시스템 | 검색→제안→기록 종단 | 시나리오 | 스테이징 |
| 인수 | UC-01~08 | 유스케이스 기반 | 스테이징 |
| 품질평가 | 검색·생성·도구선택·방어 | 지표 기반 eval | 실모델 |

## 4. 품질 평가 (Eval) 기준
| 평가 | 지표 | 기준선 | 최종 목표 | 실행 |
|---|---|---|---|---|
| 검색 | Recall@5 / MRR | 0.80 / 0.65 | 0.85 | 골든셋 30 |
| 생성 | 인용 룰체크 | 1.00 | 1.00 | 자동 검증 |
| 생성 | 충실성·유용성 | 4.0 / 3.5 | — | 모델 판정 |
| 도구선택 | 정확도 | 0.85 | 0.90 | 시나리오 20 × 3회 |
| 방어 | 인젝션 방어율 | 1.00 | 1.00 | 오염 레코드 10 |

**기준선 하향은 사람만 결정한다.** 자동화된 어떤 절차도 기준선을 낮추지 못한다.

## 5. 회귀 전략
- 커밋 단위: 정적 검사 + 단위 + 통합
- 야간: 종단 + eval 4종, 리포트를 날짜별로 보관
- 검색·프롬프트·도구 설명 변경 PR: 해당 eval 리포트 차이를 첨부해야 병합 가능

## 6. 테스트 데이터
시드 50건(사례 40, 이격 10) + 골든셋 30 + 도구 시나리오 20 + 오염 레코드 10.
오염 레코드는 **전용 테스트 데이터베이스에만** 적재한다.

## 7. 종료 기준
1. 계획된 테스트 케이스 100% 실행, 치명·중대 결함 0건
2. eval 4종 전부 기준 충족
3. 인수 시나리오(UC-01~08) 통과
4. 미해결 결함은 심각도·회피책과 함께 문서화
