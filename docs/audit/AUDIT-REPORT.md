## 감사위원 B — 실현가능성·보안

### B-1 [Critical] 유사도 임계값의 단위 오류 → 전 질의가 "미발견" 처리됨
- **위치**: specs/03 §4, .env(SIMILARITY_THRESHOLD=0.62), rag-pipeline 스킬
- **내용**: 스펙은 "**RRF 융합 점수**를 정규화 후 0.62와 비교"라고 기술. 그러나 RRF 점수는 `Σ 1/(k+rank)` 척도로, k=60일 때 이론적 최댓값이 약 0.033이다. cosine 유사도(0~1)용 임계값 0.62와 비교하면 **모든 질의가 임계값 미달**이 되어 시스템이 영원히 "사례 없음"만 반환한다.
- **판정 근거**: NFR-02(무환각)의 핵심 게이트가 정반대 방향으로 오동작. eval을 돌리는 순간 발견됐겠지만, 스펙이 소스 오브 트루스인 이 프로젝트에서 에이전트는 스펙대로 구현했을 것이다.
- **조치(수정 완료)**: 임계값은 **벡터 검색의 원시 cosine 최고점**에 적용하고, RRF는 순위 결정에만 사용하도록 specs/03·스킬·T-011/T-018 문구를 정정.

### B-2 [Major] 교차 프로젝트 읽기의 폭발 반경이 리스크 등록부에 없음
- **내용**: 읽기를 프로젝트 간 허용하는 것은 제품 취지상 옳으나, **키 1개 유출 = 전체 지식 열람**이라는 수용 리스크가 어디에도 기록되어 있지 않다. 트러블슈팅 기록에는 내부 시스템 구조·에러 경로가 담기므로 정찰 가치가 있다.
- **조치(수정 완료)**: WBS 리스크 등록부에 R7 추가 — 키 회전 절차, 접근 감사 로그, 민감 프로젝트 격리 옵션(P2)을 대응으로 명시.

### B-3 [Minor] 원격 MCP 클라이언트 제약 미기재
- **내용**: 커스텀 Bearer 헤더 방식은 Claude Code에선 동작하나, 일부 웹 클라이언트의 원격 커넥터는 OAuth를 요구할 수 있다. 1차 타깃이 Claude Code임을 명시하지 않으면 연동 단계에서 혼선.
- **조치(수정 완료)**: docs/connect.md에 지원 클라이언트 범위 1줄 추가.

### B-4 [Major] NFR-01(p95 지연) 측정 수단이 어느 태스크에도 없음
- **내용**: RTM은 "부하 측정(수동)"이라 적었지만, 부하 스크립트 작성 자체가 T-000~028 어디에도 없다. 측정 수단이 없는 NFR은 선언에 불과하다.
- **조치(수정 완료)**: T-026 Scope에 간단 부하 스크립트(k6 또는 autocannon)와 p95 기록을 추가.

### B-5 [Minor] eval 비용 상한 부재
- **내용**: 야간 eval 4종(도구 선택 20×3회 + judge)이 무기한 누적되면 비용이 예측 불가. "소형 모델·야간 한정" 문구는 있으나 예산 가드가 없다.
- **조치(권고)**: 월 예산 상한과 초과 시 eval 빈도 축소 규칙을 운영 문서에 추가할 것. (백로그)

### B-6 [Info] 검증 통과 항목
임베딩 차원(1024)–provider 일치, 마이그레이션 상태도의 롤백 경로 존재, 인젝션 3중 방어의 계층 분리, stateless 설계와 NFR-07 정합 — 이상 없음.

## 감사위원 A — 정합성·추적성

### A-1 [Major] RTM이 존재하지 않는 테스트 IT-04, IT-08을 참조
- **내용**: RTM은 FR-01 검증을 "IT-01~04", FR-07을 "IT-08"로 매핑했으나 TEST-PLAN의 TC 표에는 IT-04·IT-08이 없다. 추적성 매트릭스가 허공을 가리키면 그 행의 요구사항은 검증 불가 상태다.
- **조치(수정 완료)**: TEST-PLAN에 IT-04(수정 시 재임베딩 잡 등록), IT-08(피드백 후보 적재·미승인 제외) 추가.

### A-2 [Minor] UT-04 케이스 수 불일치 (RTM "20케이스" vs T-004 실제 25케이스)
- **조치(수정 완료)**: 25케이스로 통일.

### A-3 [Major] loop.sh가 주석과 달리 deps를 검사하지 않음
- **내용**: 주석은 "deps 충족 + STATUS 미기재"라고 주장하나 구현은 STATUS만 본다. T-011(리트리버)이 T-010(인덱스) 완료 전에 실행되어 헛돌 수 있다 — 루프 신뢰성의 근간 결함.
- **조치(수정 완료)**: 태스크 파일의 `deps:` 라인을 파싱해 loop-log.jsonl의 done 기록과 대조하는 로직 추가.

### A-4 [Major] "리포트 커밋" 정책과 nightly 워크플로 불일치
- **내용**: specs/05는 eval 리포트를 저장소에 커밋해 시계열을 남기라 했으나(포트폴리오 자산), nightly-eval.yml은 아티팩트 업로드만 한다. 아티팩트는 90일 후 소멸한다.
- **조치(수정 완료)**: 워크플로에 리포트 커밋 스텝 추가.

### A-5 [Major] `pnpm dev`(compose 기동)가 M6까지 실행 불가
- **내용**: CLAUDE.md의 로컬 개발 명령이 compose를 전제하는데 compose는 T-026(M6)에야 생긴다. M1~M5 동안 에이전트가 "명령어대로" 개발 환경을 못 띄운다.
- **조치(수정 완료)**: CLAUDE.md 명령을 단계화(`pnpm dev` = 패키지 병렬 dev 서버, `pnpm dev:compose` = T-026 이후) 하고 T-001 Scope에 dev 스크립트 추가.

### A-6 [Minor] 도면집 RTM 판(14행)과 RTM.md(17행) 드리프트
- **조치(수정 완료)**: 도면집에 FR-10, NFR-01, NFR-07 행 추가.

### A-7 [Info] contracts 시드에 Patch 스키마 부재
T-002 Scope에 명시되어 있으므로 결함 아님. 시드 파일에 미완 표시 주석만 확인.

## 종합 의견

**A**: 추적성 골격은 견고하다(요구사항→태스크→검증 사슬이 실제로 이어짐). 다만 이번에 적발된 유형 — "참조는 있는데 대상이 없음" — 은 문서가 늘수록 재발한다. `/spec-sync` 커맨드가 이미 있으므로, **RTM↔TEST-PLAN ID 대조를 CI의 spec-drift 검사에 포함**할 것을 조건으로 승인한다.

**B**: B-1은 이 감사의 존재 이유를 증명하는 결함이다. 스펙 주도 + 자동 구현 체제에서는 **스펙의 오류가 곧 구현의 오류**가 되므로, 사람 리뷰는 코드가 아니라 스펙 단계에 집중되어야 한다는 이 프로젝트의 전제를 역으로 확인했다. 수정 확인 후 승인한다.
