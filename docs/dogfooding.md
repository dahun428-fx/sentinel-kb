# 도그푸딩 — 프로토콜을 지켰는지 재고, 쌓인 것을 환류시킨다

`CLAUDE.md`의 "도그푸딩 프로토콜 (M3 이후)"은 세 줄이다: 디버깅 **전에** `search_knowledge`,
해결 **후에** `record_knowledge`, 이격은 `type: "divergence"`.

**그런데 그게 지켜졌는지 아무도 모른다.** 이 문서가 그 간극을 두 가지로 메운다.

| 장치     | 무엇을 하나                                               | 어디                                            |
| -------- | --------------------------------------------------------- | ----------------------------------------------- |
| **계측** | 주별 기록 건수·검색 적중 건수를 센다                      | `tools/dogfood-report.cli.ts` → `eval/reports/` |
| **수확** | 쌓인 divergence에서 패턴을 뽑아 하네스 수정 초안을 만든다 | `/harvest` (`.claude/commands/harvest.md`)      |

관련 스펙: `specs/00-product.md`(성공 지표·FR-07), `specs/07-mcp.md`(도구 계약),
`docs/connect.md`(다른 프로젝트를 붙이는 법).

---

## 1. 왜 계측이 먼저인가

수확은 **입력이 있을 때만** 의미가 있다. 어느 주에 초안이 0개 나왔을 때 그것이
"패턴이 없었다"인지 "아무도 기록하지 않았다"인지 구분하지 못하면, 도그푸딩이 죽은 것을
아무도 눈치채지 못한 채 몇 달이 지난다. 계측은 그 둘을 가르기 위해 있다.

그래서 `/harvest`의 0단계가 리포트 생성이고, 보고 표 맨 위에 그 주의 숫자가 붙는다.

---

## 2. 두 개의 표면 — `postmortem-interview`와 `/harvest`

둘 다 "기록을 다룬다". 역할이 겹치면 **둘 다 안 쓰이게 되므로** 경계를 여기서 못박는다.

|               | `postmortem-interview` (MCP 프롬프트) | `/harvest` (슬래시 커맨드)        |
| ------------- | ------------------------------------- | --------------------------------- |
| **시점**      | 사건 직후, 그 세션 안                 | 주 1회, 세션 밖                   |
| **입력**      | 사람의 기억 — 아직 기록이 아니다      | 이미 저장된 divergence 레코드 N건 |
| **단위**      | 사건 1건                              | 패턴 1개 (사건 2건 이상)          |
| **출력**      | 레코드 1건 (`record_knowledge`)       | 태스크 스펙 초안 (`specs/tasks/`) |
| **쓰기 대상** | 원격 KB                               | 이 레포의 파일                    |
| **누가 쓰나** | 연결된 **모든** 프로젝트의 에이전트   | 이 레포에서만                     |

한 줄 규칙: **인터뷰는 레코드를 만들고, 수확은 레코드를 소비한다.**

왜 하나는 MCP 프롬프트이고 하나는 슬래시 커맨드인가 —
인터뷰는 붙은 프로젝트 전부가 써야 하므로 **서버가 배포하는 표면**이어야 한다
(`specs/07-mcp.md` `## Prompts`가 계약으로 정해 뒀다).
수확은 이 레포의 `CLAUDE.md`·스킬·스펙을 고치는 일이라 이 레포 밖에서는 의미가 없다.
그래서 이 레포의 커맨드다.

**겹칠 뻔한 지점 하나:** 수확 도중 "아, 저것도 기록 안 했네"가 떠오르는 순간.
그때 `/harvest`는 기록하지 않고 `postmortem-interview`를 부르라고 알리고 넘어간다.
수확은 질문 순서(관측 → 종류 → 원인 → 조치 → 제목)를 지키지 못하고,
순서를 어긴 기록은 나중에 검색되지 않는다.

### 중복 기록은 어떻게 막히나

`/harvest`가 `record_knowledge`를 부르지 않으므로 **레코드 중복은 구조적으로 생기지 않는다.**
저장 전 `search_knowledge`로 중복을 거르는 책임은 인터뷰 프롬프트 §0에 있고, 거기 있어야 맞다 —
중복을 아는 유일한 시점은 저장 직전이기 때문이다.

수확이 만들 수 있는 중복은 **초안 중복**이다: 지난주에 낸 제안을 이번 주에 또 낸다.
막는 장치는 제목 유사도가 아니라 **출처 ID**다. 모든 초안은 `harvested-from: <recordId…>`를
달고, 다음 주 수확은 그 줄을 모아 이미 수확된 레코드를 후보에서 뺀다.
제목으로 판정하면 같은 패턴을 다른 말로 쓸 때마다 새 초안이 쌓인다.

## 3. 이벤트 로그 — `eval/dogfood-log.jsonl`

한 줄에 이벤트 하나. append-only. `eval/loop-log.jsonl`과 같은 규약이다.

```jsonc
{"ts":"2026-08-18T09:12:00Z","event":"search","results":3,"taskId":"T-024","query":"nginx sse 버퍼링"}
{"ts":"2026-08-18T11:40:00Z","event":"record","recordId":"...","type":"divergence","taskId":"T-024"}
{"ts":"2026-08-19T10:05:00Z","event":"hit","recordId":"...","taskId":"T-024","note":"§2 키 불일치였다"}
```

| 이벤트       | 언제 적나                                                           | 필수 필드                    |
| ------------ | ------------------------------------------------------------------- | ---------------------------- |
| `search`     | 디버깅 **전에** `search_knowledge`/`suggest_resolution`을 부른 직후 | `ts`, `results`(돌아온 건수) |
| `record`     | `record_knowledge`가 `recordId`를 돌려준 직후                       | `ts`, `recordId`, `type`     |
| `hit` (적중) | `give_feedback(helped: true)`를 보낸 직후                           | `ts`, `recordId`             |

**`results: 0`을 반드시 적는다.** 0건 검색이야말로 재고 싶은 값이다 —
"프로토콜은 지켰는데 KB가 비어 있다"와 "아무도 안 불렀다"는 고치는 사람이 다르다.
빠뜨리면 두 사건이 똑같이 "검색 0회"로 보인다.

### 왜 DB가 아니라 로컬 로그인가

`record` 건수는 서버가 뜨면 DB로 대조할 수 있다. **검색은 그렇지 않다.**
0건을 돌려준 검색은 서버에 아무 흔적도 남기지 않는데, 미스율이 정확히 그 흔적 없는 사건들이다.
그래서 이 로그는 DB의 중복 사본이 아니라 **DB가 원리적으로 모르는 것**을 담는다.
`record` 이벤트는 `recordId`를 들고 있으므로, 서버가 뜬 뒤에는 로그↔DB 대조로
"적었는데 저장이 안 된" 경우를 잡는 데도 쓸 수 있다.

### 깨진 줄은 조용히 넘어가지 않는다

로그는 손으로 덧붙이는 파일이라 깨진 줄이 생긴다. 그 줄을 건너뛰면 리포트가 조용히 작아지고,
지표가 낮은 이유가 "안 했다"인지 "로그가 깨졌다"인지 영영 구분되지 않는다.
집계기는 **줄 번호를 달고 죽고**(exit 78), 로그 파일 자체가 없어도 0건이 아니라 실패로 처리한다.

## 4. 리포트 — `eval/reports/dogfood-{ISO주}.json`

```bash
pnpm exec tsx tools/dogfood-report.cli.ts                 # 오늘이 속한 주
pnpm exec tsx tools/dogfood-report.cli.ts --week=2026-W34 # 특정 주
```

리포트 JSON은 stdout으로, 요약 두 줄은 stderr로 나간다(`mcp:ping`과 같은 규약).

주 이름은 **ISO 8601 주**(`2026-W34`)다. 달력 연도를 쓰면 연말·연초 한 주가 두 파일로 쪼개진다 —
`2024-12-30`(월)은 `2025-W01`이고 `2027-01-03`(일)은 `2026-W53`이다.

담기는 값:

| 필드                                                           | 뜻                                                                           |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `records.total` / `byType`                                     | 그 주의 기록 건수 (incident / divergence)                                    |
| `searches.total` / `withResults` / `zeroResult` / `resultRate` | 검색 횟수와 **무언가 돌아온 비율**                                           |
| `hits.total`                                                   | **적중** — `give_feedback(helped: true)` 건수                                |
| `trailing4Weeks`                                               | 최근 4주 누적을 `specs/00-product.md` 목표(기록 30건 / 적중 5건)에 대고 판정 |

`searches.withResults`와 `hits`는 **다른 것**이다. 전자는 "검색이 뭔가를 돌려줬다"이고
후자는 "그게 실제로 해결에 쓰였다"(FR-07)이다. 성공 지표의 "적중 >= 5"는 후자다 —
기록 30건에 적중 5건이라는 비율은 "결과가 나온 검색"을 세는 척도에서는 말이 되지 않는다.
둘 다 싣되 목표 판정은 `hits`로 한다.

> `eval/reports/`는 `.gitignore` 대상이다(`eval/reports/*`). 리포트는 재생성 가능하므로
> 시계열을 남기려면 커밋 정책이 따로 필요하다 — T-024 F-3 참조.

## 5. 주 1회 루틴

주간 회고 시점(금요일 또는 스프린트 종료일)에 **한 번**, 10분.

1. `/harvest`를 실행한다. 0단계에서 리포트가 먼저 나온다.
2. 리포트 두 줄을 읽는다.
   - 기록 0건 → **수확이 아니라 프로토콜 미준수 보고.** 왜 안 적었는지가 그 주의 안건이다.
   - `zeroResult`가 대부분 → KB가 얇거나 질의 표현이 어긋난 것. 골든셋 후보 논의로 넘긴다.
   - `hits` 0건 → 검색은 하는데 쓸모가 없다는 뜻. `give_feedback`을 안 보내는 것일 수도 있다.
3. 커맨드가 낸 초안·기각 표를 사람이 본다.
4. **초안을 승인한다는 것은 `specs/tasks/README.md` 표에 줄을 추가하고 `STATUS: DRAFT`를 지우는 것**이다.
   승인 전까지 초안은 태스크가 아니다.
5. 승인된 것만 `/task T-xxx`로 들어간다.

에이전트는 초안까지만 만든다. `CLAUDE.md`·스킬·스펙을 자동으로 고치지 않는다(T-024 Out of scope).
자동 적용을 막는 이유는 안전이 아니라 **되돌릴 수 없기 때문**이다 —
규칙이 한 줄씩 늘기만 하면 몇 달 뒤 아무도 CLAUDE.md를 끝까지 읽지 않는다.

## 6. 워크드 예시 — 이 레포의 실제 데이터로

**아래는 `/harvest`가 낼 산출물의 예시이고, 실제로 수확을 실행해 만든 결과가 아니다.**
MCP 서버가 아직 배포돼 있지 않아 `search_knowledge`를 부를 수 없다.
다만 인용한 레코드·문장·"미적용" 판정은 **전부 이 레포에 실재하는 것**이며,
`tools/harvest-docs.spec.ts`가 그 사실을 매 `pnpm verify`마다 대조한다.

입력이 될 divergence는 시드에 10건 있다 —
`packages/core/seed/divergence/`(DIV-01…06)와 `packages/core/seed/self/`의 divergence 4건.

### 클러스터 후보: "문서·주석의 주장이 실제와 갈라지는데 대조 장치가 없다"

| recordId | title                                                                                           | `context.tool`                           |
| -------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------- |
| SELF-03  | 루프 스크립트 주석은 deps 검사를 주장하나 구현은 STATUS만 검사                                  | `shell-script`                           |
| SELF-05  | 추적성 매트릭스가 존재하지 않는 테스트 ID를 참조 (IT-04, IT-08)                                 | `doc-authoring`                          |
| DIV-01   | 스펙은 incident 본문 섹션을 전부 선택으로 적었는데 계약 구현이 symptom·resolution을 필수로 만듦 | `implementer 에이전트 (task-loop T-002)` |

3건이고 **도구가 셋 다 다르다** — 한 사람의 습관이 아니라 축이라는 뜻이다.
세 `correction`이 서로 다른 말로 같은 것을 말한다:

- SELF-03: "주석·문서의 주장은 반드시 실행 가능한 검증(테스트 또는 CI 검사)으로 강제한다."
- SELF-05: "문서 간 참조는 사람이 지키는 규율이 아니라 기계가 검사하는 제약으로 만든다."
- DIV-01: "스키마를 생성할 때 스펙 표기와 Zod optional 여부를 대조하는 검사를 두면 이 축의 이격은 기계가 잡는다."

### 세 조건 판정

| 조건          | 판정                                                           |
| ------------- | -------------------------------------------------------------- |
| 반복 ≥ 2      | **통과** — 3건, 서로 다른 태스크·도구                          |
| 문장이 되는가 | **통과** — "문서가 주장하는 것은 기계가 대조한다"로 쓸 수 있다 |
| 아직 미적용   | **부분 적용** — 아래                                           |

부분 적용이라서 이 후보는 "규칙 추가"가 아니라 **가드 신설** 초안이 된다(커맨드 §3의 단서).
근거는 레포에서 문자열로 확인한 것뿐이다:

- `scripts/spec-drift-check.sh`가 SELF-05의 교정을 실제로 구현했다(RTM↔TEST-PLAN ID 대조).
- 그런데 `.github/workflows/ci.yml`이 그것을 `|| echo "::warning::…"`로 부른다.
  **검사는 도는데 빌드를 막지 않는다.** SELF-05의 `correction`은 "CI로 상시 검사한다"고 적었고,
  경고는 상시 검사가 아니다 — 이 격차 자체가 세 레코드가 말하는 바로 그 패턴의 네 번째 사례다.
- DIV-01의 축(스펙의 물음표 ↔ Zod optional 대조)에는 아직 아무 장치도 없다.
- `tools/connect-docs.spec.ts`(T-017)가 이 축의 **작동하는 선례**다 —
  `pnpm verify`가 막고, 도구명 정본을 `specs/07-mcp.md`에서 읽는다.

### 나온 초안(요지)

> `harvested-from: SELF-03, SELF-05, DIV-01`
> **Scope**: `scripts/spec-drift-check.sh`의 판정을 CI에서 경고가 아니라 실패로 만들고,
> `specs/02-data-model.md` 필드 표기 ↔ `packages/contracts` Zod optional 대조를 항목으로 추가한다.
> **Acceptance**: 대조를 일부러 깨뜨린 뮤테이션에서 CI가 **실패**한다 / `pnpm verify` 그린.

이 초안 파일은 이 태스크가 만들지 않았다. 초안 생성은 `/harvest` 실행의 산출물이지
T-024의 산출물이 아니고, T-024의 Context budget은 `specs/tasks/`에 다른 파일을 여는 것을 허용하지 않는다.

### 또 하나 — 수확되지 않은 채 남아 있는 것

`packages/core/seed/self/SELF-06.json`(SEV1, 여덟 라운드 fail-open)의 `correction` 세 번째 항은
"검증자가 '지적된 케이스 N종'이 아니라 **축**을 인계한다"이고,
`docs/analysis/T-004-POSTMORTEM.md` §5.2가 그것을 `.claude/skills/task-loop/SKILL.md`에 넣을
문장(`### 3.5 접근 전환 규칙`)까지 써 뒀다.

**그 문장은 오늘도 `task-loop/SKILL.md`에 없다.** 수확이 없으면 이렇게 된다 —
기록도 있고 제안 문장도 있는데 환류만 안 된다. 반복이 1건이라 세 조건 중 첫째를 통과하지 못하지만,
SEV1이고 제안 문장이 이미 있으므로 주간 보고의 **기각 표**에 남아야 한다(커맨드 §6).
`tools/harvest-docs.spec.ts`가 이 "아직 없음"을 계속 확인한다 —
들어가는 날 이 문단이 빨개지고, 그때 이 문단을 지우면 된다.

## 7. 지금 판정할 수 없는 것 — 정직하게

MCP 서버가 배포돼 있지 않고 실제 임베딩 자격증명도 없다. 그래서:

- **실제로 수확해 본 적이 없다.** `search_knowledge`를 부를 수 없으므로
  "divergence 5건 이상 입력에서 초안 1개 이상"은 판정되지 않았다(T-024 Acceptance 1).
  입력 조건(divergence ≥ 5)이 시드로 충족된다는 것만 기계로 확인했다.
- **이벤트 로그가 비어 있다.** `eval/dogfood-log.jsonl`은 0바이트다.
  없는 이벤트를 지어내지 않았다. 첫 실기록은 서버가 뜬 뒤에 생긴다.
- **4주 목표 판정은 아직 전부 `false`다.** 분모가 0이기 때문이지 성능 때문이 아니다.
