# 문서 리뷰 반영 재점검

검토일: 2026-10-21  
기준 커밋: `9e0a9ea` (T-047, 변경 파일 14개)  
비교 대상: `DOCUMENTATION-REVIEW-2026-10-21.md`

## 판정

**대부분 잘 반영됐다. 이전 주요 지적 8건 중 6건 해결, 2건 부분 해결이다.**

UPLIFT가 실제 실행에 사용할 수 있는 형태로 개선됐다. 외부 전송 경로, 심각도별 처리 규칙, 단계별 증거·중단 조건, 문서 진입점이 연결됐다. 계획 전체를 다시 작성할 필요는 없다.

다만 새로 구체화한 P3 실행 절차가 현재 Compose 설정과 충돌한다. 이 부분과 P8의 최종 승인 게이트를 수정하면 다음 작업으로 진행하기에 훨씬 명확해진다. 이미 후속으로 분리한 eval 경고 문구는 미해결 상태로 유지하면 된다.

## 남은 지적

### R1. 높음 — P3의 무자격증명 실행이 현재 설정으로는 불가능하다

근거:

- `docs/plan/UPLIFT-PLAN.md:85`: “자격증명 없이 fake embedder”로 `pnpm dev:compose` 전체 스택을 기동한다.
- `docker-compose.yml:113`: `ANTHROPIC_API_KEY`를 `${ANTHROPIC_API_KEY:?...}`로 필수 요구한다.
- `packages/core/src/llm/config.ts:60–64`: 빈 Anthropic 키를 거부한다.

**재현:** `EMBEDDING_PROVIDER=fake`, `ANTHROPIC_API_KEY` 빈 값으로 설정하고, Compose의 다른 필수 변수에는 검토용 더미 값을 주입해 `docker compose config --quiet`를 실행했다. 종료 코드 1이며 다음 오류를 확인했다.

> required variable ANTHROPIC_API_KEY is missing a value: core-api는 이 값이 없으면 부팅하지 않는다

fake embedder는 Voyage 연결만 대체한다. Anthropic 키 요구까지 없어지는 것은 아니다.

**권장 수정:** 현 구조를 유지한다면 P3에 Anthropic 키 설정이 필요하다고 명시한다. “자격증명 없이”가 Voyage 키만 뜻했다면 “Voyage 키 없이, fake embedder 사용; Anthropic 키는 필요”로 범위를 좁힌다. 완전한 무자격증명 실행을 원한다면 검색 전용 또는 fake LLM 실행 경로를 별도 구현 태스크로 정의해야 한다. 임의 더미 키로 기동시키는 것만으로 생성 기능의 실행 검증을 통과했다고 판단하면 안 된다.

### R2. 중간 — 승인 기준의 수치는 정리됐지만 최종 완료 조건과 연결되지 않았다

근거:

- `UPLIFT-PLAN.md:173–180`: 중간 기준과 승인 기준을 구분하고, 승인 기준 미달 시 재평가 시점을 적도록 했다.
- `:146`: P8 완료 판정은 4주·신규 기록 30건·도움됨 피드백 5건뿐이다.
- `:37`: P8 통과 후 사내 확장을 판단한다.

이대로면 Recall@5 0.82 상태에서 재평가 일정을 적은 뒤, 사용량 조건만 채워 P8을 통과할 수 있다. 기준의 의미는 명확해졌지만 “언제 충족해야 하는가”는 여전히 느슨하다.

**권장 수정:** P8 완료 증거에 “§3-1 승인 기준을 충족한 최종 평가 리포트”를 추가한다. 또는 도그푸딩 완료와 제품 실사용 승인을 별도 상태로 나누고, 사내 확장은 후자 통과 뒤 판단하도록 적는다. 낮은 중간 기준으로 개인 도그푸딩을 시작하는 것 자체를 막을 필요는 없다.

### R3. 낮음 — 실행 시 출력되는 오래된 차단 안내는 남아 있다

근거: `eval/retrieval/golden-set.ts:94`는 여전히 `seedBatch` 마커·G3 결정을 선행 조건이라고 출력한다.

문서와 머리 주석에는 대체 구현·해소 표시가 추가됐다. 그러나 CLI를 실행하는 사용자는 오래된 안내를 계속 받는다. 이 항목은 T-047의 Out of scope와 Findings F-1/F-2에 이미 정확히 기록돼 있다. 누락된 수정으로 단정할 사안은 아니며, **완료로 닫지 않고 후속 태스크로 처리하면 된다.**

**권장 수정:** 경고 문자열과 이를 검증하는 테스트 기대값을 실제 선행 조건인 실 임베딩 자격증명·골든셋 작성으로 맞춘다. 테스트 통과를 위해 기준을 낮추는 변경이 아니라, 잘못된 안내를 바로잡는 변경이다.
