## UC-01 유사 사례 검색
- **주액터**: A1 대응 에이전트
- **사전조건**: 유효한 Bearer 키. 검색 인덱스 READY.
- **사후조건**: 결과 목록 반환. 시스템 상태 변경 없음.
- **트리거**: 에이전트가 에러를 만나 디버깅을 시작하기 전.

**기본 흐름**
1. A1이 질의 텍스트와 선택적 필터를 전달한다.
2. 시스템이 인증하고 프로젝트 스코프를 해석한다.
3. 시스템이 질의를 임베딩한다. `[S1]`
4. 시스템이 벡터 검색과 키워드 검색을 각각 수행한다. `[S3]`
5. 시스템이 두 결과를 RRF로 융합하고 레코드당 최대 2청크로 정리한다.
6. 시스템이 요약과 레코드 ID로 구성된 목록을 반환한다(본문 미포함).

**대안 흐름**
- 3a. 임베딩 호출 실패 → 키워드 검색 단독으로 진행하고 응답에 `degraded` 표시.
- 5a. 결과 0건 → 빈 목록과 함께 기록 권유 메시지를 반환한다.

**예외 흐름**
- 2a. 인증 실패 → `401 UNAUTHORIZED`.
- 4a. 인덱스 미준비 → `503 INDEX_NOT_READY`.

**특이 요구**: 응답 토큰 예산 준수(NFR-03), p95 < 1.5s(NFR-01).

## UC-02 해결책 제안 받기
- **주액터**: A1
- **사전조건**: UC-01과 동일.
- **사후조건**: 인용이 포함된 제안 또는 미발견 응답.

**기본 흐름**
1. A1이 에러 텍스트를 전달한다.
2. 시스템이 UC-01의 검색을 수행한다.
3. 시스템이 최고 유사도를 임계값과 비교한다.
4. 충족 시, 인용 강제 프롬프트로 답변을 생성한다. `[S2]`
5. 시스템이 인용 유효성을 후처리 검증한다.
6. 원인 가설·해결 절차와 인용 레코드 목록을 반환한다.

**대안 흐름**
- 3a. **임계값 미달** → LLM을 호출하지 않고 `미발견 + 기록 권유`를 반환한다. (NFR-02)
- 5a. 인용 위반 → 1회 재생성. 재차 위반 시 무인용 문장을 제거하고 위반을 로깅한다.

**예외 흐름**
- 4a. LLM 호출 실패 → 검색 결과 목록만 반환하고 생성 실패를 명시한다.

**특이 요구**: 검색된 본문 내부의 지시문을 따르지 않는다(NFR-05).

## UC-03 사례 기록
- **주액터**: A1, A2
- **사전조건**: 유효한 키.
- **사후조건**: 레코드 저장 + 인제스트 잡 등록.

**기본 흐름**
1. 액터가 제목·증상·해결 등 섹션을 전달한다.
2. 시스템이 스키마를 검증한다.
3. 시스템이 새니타이즈를 수행한다. (FR-06)
4. 시스템이 `project`를 인증 키에서 주입해 저장한다.
5. 시스템이 요약을 생성하고 인제스트 잡을 등록한다.
6. 시스템이 레코드 ID와 플래그를 반환한다.

**대안 흐름**
- 3a. 자격증명 탐지 → 마스킹 후 저장하고 **무엇이 마스킹됐는지 응답에 포함**한다.
- 3b. 인젝션 의심 패턴 → 플래그를 부여하되 본문은 보존한다.
- 5a. 잡 등록 실패 → 레코드는 유지하고 재시도 큐로 넘긴다.

**예외 흐름**
- 2a. 필수 섹션 누락 → `400 VALIDATION_FAILED` + 누락 필드 목록.

## UC-04 이격 기록
- **주액터**: A1, A2
- **차이점**: UC-03과 흐름은 같으나 필수 필드가 `expected`, `actual`, `correction`이며 `context`(모델·도구·프레임워크)를 요구한다.
- **사업 규칙**: `correction`은 "다시 지시했더니 됐다"가 아니라 **무엇을 명시했더니 해결됐는지**를 담아야 한다. 재현 조건이 없는 이격은 지식으로 성립하지 않는다.

## UC-05 레코드 전문 조회
**기본 흐름**: 액터가 레코드 ID를 전달 → 시스템이 전문을 데이터 블록으로 래핑해 반환(지시 무시 고지 포함) → 플래그를 함께 표시.
**예외**: 존재하지 않는 ID → `404 RECORD_NOT_FOUND`.

## UC-06 피드백 제출
**기본 흐름**: 액터가 레코드 ID와 도움 여부를 전달 → 저장 → 골든셋 후보로 적재.
**사업 규칙**: 후보는 자동 승격되지 않는다(UC-07).

## UC-07 골든셋 승인
**기본 흐름**: A4가 후보 목록을 검토 → 승인/기각 → 승인분만 eval 러너가 사용.
**사업 규칙**: 골든셋 오염은 품질 지표 전체를 무의미하게 만든다. 승인은 사람만 한다.

## UC-08 임베딩 모델 교체
**기본 흐름**: A4가 버전을 올린다 → 전체 재임베딩을 신규 버전으로 삽입 → 인덱스 준비 확인 → 검색 필터를 신규 버전으로 전환 → 구버전 청크 삭제.
**사업 규칙**: 인플레이스 갱신 금지. 전환 중에도 검색은 계속 동작해야 한다(NFR-06).
