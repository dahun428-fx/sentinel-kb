## 첫 주 순서 (수동 → 자동 전환)

1. **손으로**: T-001 스캐폴드를 직접 만든다. 루프가 돌 바닥이 없으면 루프를 못 돈다
2. **손으로**: `.claude/` 전체와 CLAUDE.md를 레포에 넣는다 (이 스캐폴드 그대로)
3. **루프로**: `MAX_TASKS=1 ./scripts/loop.sh` → T-000 완결 확인.
   여기서 프로토콜 준수 여부를 눈으로 검사한다 — PLAN 선언했나, budget 밖 읽었나, 로그 남겼나
4. 문제가 있으면 **스킬을 고친다.** 프롬프트를 그때그때 보태지 않는다 (그러면 다음 세션에 사라진다)
5. **루프로**: `MAX_TASKS=5 ./scripts/loop.sh` → T-002~006 배치 실행. 아침에 PR 5개를 리뷰한다

## 사람이 시간을 쓰는 곳 (여기만)

1. **태스크 스펙 작성·승인** — 스펙이 곧 프롬프트다. 최대 레버리지 지점
2. **G3/G6 BLOCKED 해소** — 계약 변경 판단
3. **PR 머지** — eval diff 확인
4. **골든셋 승인** — 오염되면 루프 전체가 무의미해진다

나머지는 루프가 한다. 자동 완결률 70%가 목표고, 미달이면 **스펙 서술을 개선한다**(에이전트를 탓하지 않는다).

## 루프가 잘 안 돌 때 진단 순서

| 증상 | 원인 | 조치 |
|---|---|---|
| 매번 Context budget을 넘김 | 태스크가 너무 크다 | 태스크를 쪼갠다 |
| Acceptance를 자의적으로 해석 | 판정이 기계적이지 않다 | 명령어 기반으로 다시 쓴다 |
| 스코프를 계속 넘음 | Out of scope가 비어있다 | 명시적으로 채운다 |
| 같은 실수 반복 | 규칙이 세션에만 있었다 | 스킬 또는 CLAUDE.md로 승격 |
| eval을 고치려 함 | 지시가 약하다 | task-loop 스킬의 중단 사유를 강화 |

이 진단 표 자체가 divergence 기록의 원형이다. M3 이후엔 이걸 sentinel-kb에 기록하고 `/harvest`로 수확한다.

## 재귀 구조 (포트폴리오의 핵심 서사)

```
sentinel-kb를 만들면서 겪은 트러블슈팅·이격
   → sentinel-kb에 기록 (M3 이후 자기 자신에 연결)
   → /harvest로 패턴 수확
   → CLAUDE.md·스킬 개선 태스크 생성
   → 다음 태스크의 자동 완결률 상승
```
"자기 자신으로 자기를 개발한다." 이 루프가 돌았다는 증거(loop-log.jsonl + divergence 기록)가
제품 자체만큼이나 강한 산출물이다.
