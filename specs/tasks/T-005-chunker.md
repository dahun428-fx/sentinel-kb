## Findings

### 스펙 수정 (인간 사후 비준 대상)
- **S-1 `specs/03` §1-2의 분할 트리거를 "섹션 1200자 초과" → "완성 청크 텍스트(prefix 포함)
  `CHUNK_MAX_CHARS` 초과"로 정정.** 상한의 목적이 임베딩 입력 예산인데, 실제 임베딩되는 텍스트는
  `[title] (section) ` prefix를 포함한 완성 청크다. 본문 기준으로 재면 제목 길이만큼 상한을 넘겨
  임베딩된다(제목은 contracts에서 200자까지 허용되므로 최대 217자 초과).
  대가로 긴 제목이 본문 예산을 잠식하지만, 그건 총량이 예산이라는 정의의 귀결이다.
  **정정 전에는 테스트가 구현 해석을 스펙인 양 고정하고 있었다** — G5가 이를 잡았다.

### 후속 태스크가 반드시 알아야 할 것
- **F-1 `chunk.embeddingVersion`의 소스가 미정의다.** `record.embeddingVersion`인지 embedder의
  `EMBEDDING_VERSION`인지 어느 스펙에도 없다. specs/02 마이그레이션 규칙("전체 재임베딩 =
  신규 버전 삽입 → 필터 스왑 → 구버전 삭제")대로면 **embedder 쪽**이어야 하는데, 그러면
  재임베딩 중 `record.embeddingVersion`과 어긋난다. `ChunkSchema`가 `.strict()`라
  뒤늦게 바꾸려면 contracts 재개방(G3)이 걸린다. **T-006/T-008에서 결정.**
- **F-2 재청킹 시 고아 청크가 남는다.** greedy packing이라 본문 앞쪽이 바뀌면 뒤 조각 경계가 밀린다.
  upsert는 같은 키를 덮어써 중복은 안 생기지만, **청크 수가 줄어드는 수정에서는 꼬리 청크가
  구 본문·구 임베딩을 단 채 검색에 계속 잡힌다.** specs/03에도 T-008 Scope에도
  "재청킹 시 잔여 청크 삭제" 단계가 없다. **T-008에서 반드시 처리.**
- **F-3 레코드 1건이 청크 28개까지 간다 — T-011의 재현율 붕괴 경로.**
  specs/03 §2의 `dedupeByRecordId`(record당 최대 2청크)는 융합 **후**에 걸린다.
  그런데 `$vectorSearch(limit=RETRIEVAL_VECTOR_K=20)` 후보 리스트는 dedupe **이전**이라,
  28청크짜리 레코드 하나가 20슬롯을 통째로 점유하면 dedupe 후 **최종 결과에 레코드가 1건만 남는다.**
  chunker에 청크 수 상한을 두는 건 답이 아니다 — 스펙 근거가 없고 지식을 조용히 버린다.
  **T-011에서 후보 K를 dedupe 손실분만큼 키우거나 섹션 다양성을 후보 단계에서 확보할 것.**
- **F-4 `CHUNK_MAX_CHARS` 기본값 1200이 세 곳에 있다** (`chunker/config.ts`, `.env.example`,
  `chunk-record.spec.ts`). T-003 F-8(`MONGODB_SERVER_SELECTION_TIMEOUT_MS`)과 같은 축이다.
- **F-5 `prefix.length >= maxChars`면 상한이 조용히 깨진다.** `Math.max(1, maxChars - prefix.length)`
  가드 때문에 제목 200자 + `CHUNK_MAX_CHARS=100` 조합에서 **청크 3000개가 각각 214자로** 나온다.
  §6이 eval 스윕을 위해 env화를 요구하므로 작은 값 스윕은 가상 시나리오가 아니다. → 이번에 수정.
- **F-6 배럴 등재 규칙이 신규 관례다.** "무거운 런타임 의존(mongodb)을 끌면 서브패스, 아니면
  메인 배럴" — 어느 스펙에도 없다. `./db`는 서브패스, chunker는 배럴로 갈린 근거가 이것뿐이다.
- **F-7 divergence의 `context`(model/tool/framework)는 청킹 대상이 아니다.**
  `ChunkSection` 열거에 없기 때문이며 의도적이다. 다만 도그푸딩 프로토콜이 "모델·도구·재현 조건
  포함"을 요구하므로 검색 신호로는 쓸모가 있다. 섹션으로 올리든 `meta`에 비정규화하든
  specs/02·03 수정이 필요한 사안이라 여기서는 건드리지 않았다.
- **F-8 `T-013` 골든셋은 recordId 기준이라 재라벨링이 불필요하다.** 다만 `CHUNK_MAX_CHARS`를
  스윕하면 청크 경계→임베딩→랭킹이 전부 바뀌어 **Recall@5·MRR 기준선을 재수립**해야 한다.
  "기준선을 낮추는 커밋 금지"(CLAUDE.md)와 충돌할 수 있으므로 스윕 시 갱신 절차를 명시할 것.

### 검증에서 나온 것 — 수정 완료
- **서로게이트 쌍 분할 (데이터 손상).** `hardCut`이 `slice`로 UTF-16 **코드 유닛** 단위 절단을 해서
  비-BMP 문자(이모지)가 반으로 갈렸다. **기본 설정(1200)에서 재현**됐고 퍼즈 500케이스 중 3건 발생.
  고아 서로게이트는 UTF-8 인코딩 순간 U+FFFD로 치환되어 **되돌릴 수 없다** —
  청크는 임베딩 API 페이로드와 MongoDB(BSON=UTF-8)로 나가므로 손상이 그대로 굳는다.
  발동 조건은 "경계도 종결부호도 없는 예산 초과 토큰 + 홀수 오프셋의 비-BMP 문자"로,
  한 줄 JSON 로그·base64·긴 URL에 이모지가 섞이면 걸린다. **트러블슈팅 KB에 로그를 붙여넣는 건 주 용례다.**
  → 절단면이 상위 서로게이트면 한 칸 물러 쌍을 온전히 남긴다.
- **Acceptance 2가 검증되지 않고 있었다.** "문장이 중간에서 잘리지 않음" 테스트의 픽스처가
  문단 4개로 돼 있어 **탐욕 패킹이 문단 경계만으로 예산을 맞춰 문장 분할 코드가 한 번도 실행되지 않았다.**
  게다가 모든 문단이 `다.`로 끝나 `/다\.$/` 단언은 아무 데서나 잘라도 통과하는 자기충족적 단언이었다.
  실제로 문장 경계 규칙을 통째로 제거해도 18개가 전부 그린이었다(단어 중간이 잘리는데도).
  → 픽스처를 **문단 경계 없는 산문**으로 바꾸고, 단언을 "각 조각이 원문 문장 목록의 **연속 부분수열**"로
  강화했다. 문단 경계 테스트도 같은 방식으로 바꿨다 — 종결부호 단언만으로는 `\n\n`→`\n` 완화를 못 잡는다.

뮤테이션 잠금 확인: 서로게이트 가드 제거 2 failed, 문장 경계만 제거 1 failed,
문단 경계 완화 1 failed, F-5 예산 가드 제거 2 failed.

### 확인된 것 (결함 없음)
퍼즈 500케이스(maxChars 1200/300/120/60 스윕) 결과:
**본문 유실 0, 중복 0, 상한 초과 0, 빈 청크 0, seq 연속성 정상, 결정론 100회 동일.**
폭 0 lookaround로 토큰을 나눠 이어붙이면 원문이 복원된다는 설계는 주장대로 작동한다.

### 재검증 후 정리 (머지 전)
- **F-C 죽은 폴백 제거.** `if (end <= index) end = index + budget;`은 `MIN_BODY_BUDGET` 가드가
  먼저 막아 도달 불가능한 코드였는데, **남겨두면 그 가드가 완화되는 순간 손상 경로가 부활한다**
  (실측: 가드를 1로 낮추면 budget=1에서 40개 청크 전부가 고아 서로게이트가 됐다).
  대신 `hardCut` 자신이 `budget < 2`를 검사해 불변식을 함수 안에서 못박는다.
- **F-E `ChunkBudgetError`를 배럴에 노출.** T-008 워커가 `instanceof`로 잡아야 하는데
  `@sentinel/core`에서 가져갈 수 없었다. `code` 문자열 비교로 우회하면 이 클래스를 만든 이유가 반감된다.
- **F-D 서로게이트 경계 양끝 회귀 테스트 추가.** `0xD800`(U+10000~)·`0xDBFF`(~U+10FFFF)를
  off-by-one으로 놓치면 그 두 평면만 조용히 깨진다. **테스트에 pad를 넣어 오프셋을 미는 것이 핵심** —
  절단면이 짝수에 떨어지면 백오프가 아예 발동하지 않아 경계 판정이 틀려도 통과한다(1차 시도에서 실제로 그랬다).

뮤테이션 최종: 서로게이트 가드 제거 2 failed, 상한 off-by-one 1 failed, 하한 off-by-one 1 failed,
배럴 export 제거 1 failed, 문장 경계만 제거 1 failed, 문단 경계 완화 1 failed, 예산 가드 제거 2 failed.

### 남은 것
- **F-A 그래핌 클러스터가 강제 절단 경계에서 쪼개진다 (품질, 손상 아님).**
  🏳️‍🌈·👨‍👩‍👧‍👦·🇰🇷 같은 ZWJ·regional indicator 시퀀스가 갈린다. 고아 서로게이트도 U+FFFD도 아니고
  이어붙이면 원문이 복원되므로 데이터 손상은 아니다. 렌더 깨짐과 임베딩 토크나이즈 품질 저하만 있다.
  `Intl.Segmenter` 기반 그래핌 경계 절단이 정공법이나 결정론·성능 검토가 필요하다.

  `specs/03`에도 `.env.example`에도 없다. 문면화 필요.
